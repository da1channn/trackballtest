# Endgame 1.5.3 ボタン診断用ビルド

診断用ファームのビルドと確認手順です。完成UF2はActionsの成功した実行のArtifactsから取得します。実機未検証です。

2026-09-25: [ビルド・自動検査成功](https://github.com/da1channn/trackballtest/actions/runs/36099798887)。診断UF2は867,328 bytes、SHA-256 `c77232ddc7b8b0e080b75708c7b2fa37f737ad1086ce3fad4bfa976a07ea877d`。書き込み範囲は元の1.5.3と同じ0x1000–0x6ADFFで、設定保存領域0x6C000以降を含みません。診断ログ文字列とプロンプトをバイナリ内で確認済みです。

## 目的

基板rev08で使用中のEndgame 1.5.3を基に、割り当て処理より前のボタン入力をUSBログに出します。
既存のGPIOスキャン処理が検出した状態変化を記録します。入力端子を独立して直接読む別実装ではないので、無反応の場合に回路とGPIO設定を完全に区別することはできません。

変更は押下ログ1箇所をINFOへ変更すること、ZMKログレベル3の明示、端末プロンプトの変更です。ピン割り当て、レイヤー、長押し判定、スキャン、デバウンス、ペアリング設定、ブートローダーは変更しません。設定初期化用ファームは含みません。

## ビルドする

1. GitHubで診断専用リポジトリを作ります。READMEを追加して初期化してください。
2. 同梱の `endgame-diagnostic.yml` を `.github/workflows/endgame-diagnostic.yml` というパスで登録します。
3. Actionsの「Endgame 1.5.3 button diagnostic」が緑で完了するまで待ちます。
4. 成果物「Endgame-1.5.3-button-diagnostic-v1」をダウンロードすると、UF2・構成・検証結果が入っています。

ActionsにはGitHub側の利用枠・実行可否が適用されます。このワークフローはリリース公開や機器への書き込みは行いません。

## 書き込み後の確認（ビルド成功・成果物確認後）

通常の1.5.3 UF2は復旧用に手元へ残します。PuTTYを閉じ、これまで使用したEndgameのブートローダー起動手順でUF2ドライブを表示させ、診断UF2をコピーします。ドライブ消失後、USBを接続し、PuTTYをCOM6・115200・8N1・Flow control Noneで開きます。COM番号が変わったらデバイスマネージャーで確認します。

Enterで `endgame-diag1$` が出ることを確認します。これは診断版が起動している目印です。
正常なボタンをゆっくり押して離し、DOWNとUPの2行が出ることを先に確認します。次に問題の手前右下ボタンを押して離します。試験中はPuTTYの画面外へカーソルを移動してください（右クリックによる文字の貼り付けを防ぐため）。

想定ログ（出力例であり、実機から取得したものではありません）:

```text
<inf> zmk: EGDIAG1 button=7 pin=7 state=DOWN
<inf> zmk: EGDIAG1 button=7 pin=7 state=UP
```

| 正面から見た位置 | button番号 | gpio0ピン番号 |
|---|---:|---:|
| 最上段・左 | 0 | 27 |
| 最上段・右 | 1 | 26 |
| 左側面・上 | 2 | 1 |
| 右側面・上 | 3 | 4 |
| 左側面・下 | 4 | 21 |
| 右側面・下 | 5 | 5 |
| 最下段・左（手前） | 6 | 8 |
| 最下段・右（手前、今回の対象） | 7 | 7 |

位置対応は1.5.3のbuttons.dtsiに基づきます。ダイヤル回転はこの8ボタン用ログの対象外です。

| 結果 | 判断 |
|---|---|
| 右下のDOWN/UPが出る | 少なくともその試行では入力を検出。割り当て・レイヤー・送信先を調査 |
| 他は出るが右下だけ出ない | 右下の回路・入力ピン設定・スキャン経路を調査。MCU故障の断定は不可 |
| すべて出ない | 診断プロンプトとログ経路を確認。回路判定は保留 |
| 1回の押下でDOWN/UPが多数出る | 接点・配線・機械的な押し込み・デバウンスを調査 |

診断後は同じ方法で手元の通常1.5.3へ戻せます。診断ログには処理負荷があるため、マウスの滑らかさの比較には使用しません。
